# Hydra 2.0 Track-3 — Calibrated Benchmark — Design Spec

- **Status:** Draft (awaiting plan)
- **Date:** 2026-05-26
- **Author:** Franz (via Claude)
- **Builds on:** Track-2 (`docs/specs/2026-05-26-hydra-2.0-track2-deterministic-engine.md`) — branch `feat/track3-calibrated-bench` stacks on `feat/track2-deterministic-engine`.
- **Depends on:** ADR 0001 (Option C — bench-scoped engine, `claude --print` invocation).

---

## 0. Why this spec exists

Track-2 delivered a **sound smoke harness with an honest advisory gate** (deterministic grounding + hybrid scorer + critical-recall gate). A 7-specialist audit (AI-eval / AI-harness / 5 agentic-eng) established that it is **not yet a calibrated benchmark**: the construct ceilings (1 mandatory GT/case → recall pinned at 1.0), the baseline is a selection-biased single retried run, the gate is therefore advisory-only, the report→candidate seam is brittle prose-scraping, and the judge is uncalibrated.

Track-3 raises the bench from *smoke* to *calibrated*: a benchmark whose metrics have dynamic range, whose baseline carries characterized variance (bootstrap CIs), whose gate can **block** with a known false-positive rate, whose findings come from a **structured contract** not prose, and whose LLM judge has **measured accuracy/bias**.

### Recorded decisions (forks resolved 2026-05-26)
- **D-3.1 (cases):** Expand the synthetic cases to multi-finding (mandatory + optional GT) + benign distractors; add a few new cases. Hermetic; defer real git-submodule upstream cases (Task-35).
- **D-3.2 (substrate):** Keep `claude --print` (plan-billed); add statistical rigor — capture-all + median-of-N (N≈5) + bootstrap CIs + telemetry; gate on the CI. No direct-SDK advisor driver (respects ADR D-2).
- **D-3.3 (contract):** The skill emits a machine-readable `*.findings.json` sidecar; the bench consumes it via `extract_from_structured`, with prose-scraping retained only as the 1.x fallback.

## 1. Scope & Non-Goals

### In scope (5 components, phased)
- **A — Structured findings contract** (sidecar; kills prose-scraping). *Touches the shipped skill.*
- **B — Multi-finding cases + distractors** (construct validity; metrics gain range).
- **C — Statistical baseline** (capture-all, median-of-N, bootstrap CIs, telemetry; blocking gate).
- **D — Judge calibration** (gold-set accuracy/bias, stability, seed, telemetry).
- **E — Threshold calibration** (regression threshold from observed σ; CITATION_THRESHOLD TP/FP sweep).

### Non-Goals
- **No direct-SDK advisor driver / no OpenAI-Codex client** (ADR D-2; D-3.2).
- **No real git-submodule upstream cases** (Task-35) — deferred to a later phase; synthetic multi-finding first.
- **No change to interactive review *behaviour*** — the sidecar is an *additive* machine-readable emit alongside the existing `.md` report; the human report and verdict logic are unchanged.
- **No new advisor / roster change.**

## 2. Component A — Structured findings contract (sidecar)

**Problem:** the bench regex-scrapes a human Markdown report (`extract_from_report`); the format already drifted 3× (integrity comment, em/en-dash, comma-spans). An LLM free-writes the prose layout — a non-contractual API.

**Design:**
- `/hydra` writes, alongside `.hydra/reports/hydra-<ts>-<slug>.md`, a sibling
  **`.hydra/reports/hydra-<ts>-<slug>.findings.json`** — a JSON object:
  ```json
  { "schema_version": "1.0",
    "findings": [ {AdvisorFinding-shaped: id,title,severity,file,lines,issue_class,evidence,position,chain} ] }
  ```
  `findings[]` is the **full** action/finding set (not the "top N" of frontmatter `top_actions`).
- **Skill changes (additive, small):** `references/report-template.md` + `SKILL.md` report-writing step gain a "also write the `.findings.json` sidecar" instruction, mirroring the existing `.hydra/state.json` emit. Reuse the existing `AdvisorFinding` field names so the bench parses with `bench/runner/extract_findings.extract_from_structured` (already built).
- **Bench changes:** `invoke_hydra` returns the sidecar path when present; extraction prefers `extract_from_structured(sidecar)`, **falls back** to `extract_from_report(.md)` (1.x / missing sidecar). A `schema_version` mismatch fails loud.
- **Why not `--output-format json`:** that envelope carries Claude's *response* + usage/cost (control-plane, useful for telemetry — adopt for B), but the *findings* are the skill's domain artifact and belong in the skill-emitted sidecar (data-plane). Use both: envelope for cost/error signal, sidecar for findings.

**Risk/mitigation:** touches the shipped product. Mitigate by making it purely additive (no behaviour change), version-gated, and covered by a fixture test (a captured real sidecar) so drift fails in CI.

## 3. Component B — Multi-finding cases + benign distractors

**Problem:** 1 mandatory GT/case → recall pinned at 1.0 (no improvement headroom), precision ∼1/k penalizes thoroughness, F1 degenerate.

**Design:**
- **Multi-finding GT:** each case's `expected_findings.jsonl` carries **2-4 findings** — a mix of `mandatory: true` (the seeded core bug) and `mandatory: false` (secondary real issues a strong reviewer should also catch). Gives `recall` real range and keeps `critical_recall` (mandatory-only) as the gate metric.
- **Benign distractors:** seed code in the case `workspace/` that *looks* suspicious but is correct (a guarded `eval` behind a constant, a TODO that's already handled, a deliberately ugly-but-safe pattern). A reviewer that flags a distractor produces a candidate matching **no** GT → lowers precision. To measure FP-resistance explicitly, add an optional **`negative_anchors`** file (`bench/cases/<id>/negative_anchors.jsonl`: `{file, lines, why_benign}`) — a candidate overlapping a negative anchor is counted as an explicit **false positive** (distinct from generic noise).
- **Schema additions (additive, `GroundTruthFinding`):** add `description: str` (human-readable bug description — gives the judge real semantics, not just keywords; judge-specialist finding) and keep `must_mention` (now: prefer a discriminating anchor term, not generic tokens — eval F3). Optionally split `must_mention_all` (discriminating) vs supporting terms.
- **New cases:** add ~3 cases for breadth/category coverage (concurrency, data, api) so n grows from 5 → ~8 (improves statistical power).
- **Metrics gain meaning:** recall/precision/F1 now move; add `false_positive_rate` (negative-anchor hits / candidates) as a first-class quality axis.

## 4. Component C — Statistical baseline (capture-all + CIs + blocking gate)

**Problem:** the baseline is a selection-biased *best-of-retry* single run; comparing it to future medians systematically biases the challenger; the gate is advisory.

**Design:**
- **Capture-all, discard nothing:** every attempt recorded as `{case, mode, attempt, outcome ∈ {scored, timeout, no_report, action_less}, duration_s, candidate_count, scores}` to a run-log JSONL. The retry loop **records**, it does not cherry-pick.
- **Baseline = distribution, not point:** per case/mode, capture **N≈5 scored runs**; store **median + bootstrap 95% CI** (2.5/97.5 percentile) per metric, plus **harness success-rate** (scored / attempts) as a first-class field.
- **Blocking gate on CI:** a regression fires when **2.0's metric CI upper-bound < 1.x's CI lower-bound** on ≥2 cases (non-overlapping CIs = real difference), gated on **critical-recall** (primary) with recall/F1/FP-rate reported. This replaces the σ-free ≥10pp heuristic with a CI-based test of known false-positive rate.
- **Harness-failure ≠ regression:** the Track-2 guard stays — zero scored runs → exit 2 (infra), not exit 1 (regression). Report success-rate; if success-rate itself regresses, that's a *flakiness* signal reported separately.
- **Telemetry surfaced:** the bench prints success-rate + failure-mode breakdown every run (already started in Track-2 `_print_telemetry`).
- **Cost (D-3.2):** plan-billed `claude --print`. Calibration baseline ≈ N(5) × cases(~8) × standard mode = ~40 scored runs (+ retries for ~50% flakiness ≈ ~80 invocations), ~several hours wall, plan-billed (no API $). Deep-mode + N×3 full is a later, costlier pass. **Budget/time confirmed before the capture run (Component-C phase gate).**

## 5. Component D — Judge calibration

**Problem:** the judge (LLM-as-judge) has unmeasured accuracy/bias; temperature=0 ≠ deterministic; runs only on the keyword-fail subset (two-tier grading).

**Design:**
- **Gold-set** `bench/judge_gold.jsonl`: hand-labeled `{gt, candidate, expected: MATCH|NO_MATCH}` pairs incl. **adversarial near-misses** (same location, different bug → NO_MATCH; correct paraphrase → MATCH; persuasive-but-wrong candidate → NO_MATCH). ~20-30 pairs.
- **Measured accuracy/bias:** a (key-gated) integration test runs the judge over the gold-set and asserts accuracy ≥ threshold + reports the MATCH/NO_MATCH confusion (position/leniency bias).
- **Stability:** run the judge N× on a fixed borderline pair; assert agreement rate (quantifies temp-0 nondeterminism).
- **Seed + provenance:** pass `seed=` if the SDK exposes it for the judge model; record judge model id + judge-decided-match **count** per run in the baseline (so a baseline's non-determinism is visible).
- **Reduce two-tier grading (eval F4):** consider running the judge as the **sole arbiter** on all file+range-passing candidates (keywords become a logged feature), or keep keyword fast-path but record the judge-decided fraction. Decision deferred to the judge-calibration phase, informed by gold-set accuracy.

---

## 6. Component E — Threshold calibration

- **Regression threshold from observed σ:** using the capture-all distribution (Component C), compute per-case metric variance and set the CI-overlap / drop threshold so the gate's false-positive rate is a **known α** (e.g. ≤5%), documented. Replaces the heuristic 10pp/15pp constants.
- **`CITATION_THRESHOLD` TP/FP sweep:** now that multi-finding cases provide grounding signal, sweep the 0.4 starting value against a labelled TP/FP set of (finding, cited-range) pairs; pick the value maximizing grounding F1; freeze + document. (Grounding-based **hallucination scoring**: a candidate whose citation grounding fails → flagged as a likely hallucination, a quality axis tying Pillar A into the bench.)

## 7. Metrics redesign (summary)

| Metric | Track-2 (smoke) | Track-3 (calibrated) |
|---|---|---|
| recall | pinned 1.0 (1 GT) | dynamic (multi-GT) |
| precision | pinned ∼1/k | meaningful (distractors + negative anchors) |
| F1 | degenerate, diagnostic | informative diagnostic |
| **critical_recall** | gate (binary) | **gate** (mandatory subset, multi) |
| false_positive_rate | — | NEW first-class (negative anchors) |
| hallucination_rate | — | NEW (grounding-based) |
| harness success-rate | — | NEW first-class (capture-all) |
| baseline | single retried run | **median + bootstrap CI over N≈5** |
| gate | advisory | **blocking on non-overlapping CIs, known α** |

## 8. Phasing & sequencing

1. **P1 — Sidecar contract (A):** skill emits `*.findings.json`; bench prefers it (`extract_from_structured`) + prose fallback; fixture test. *(Unblocks robust extraction; small skill change.)*
2. **P2 — Multi-finding cases + distractors (B):** schema additions (`description`, negative anchors); expand 5 cases to multi-GT + distractors; +~3 new cases; FP-rate metric.
3. **P3 — Statistical baseline (C):** capture-all + telemetry + median-of-N + bootstrap CIs; CI-based blocking gate; harness-failure exit code. **OFFLINE CORE SHIPPED (P3a 204770a, P3b 7da51ef):** `bench/runner/stats.py` (`bootstrap_ci`, `ci_regression`, `success_rate`) + `write_ci_baseline`/`gate_against_ci_baseline`/`aggregate_outcomes`/`metric_cis` in run_bench + `_run_mode` auto-detects `statistical:true` baselines → CI gate (legacy single-run → advisory gate retained); per-case success-rate + failure-mode telemetry. **DEFERRED to P6 (live, cost-gated):** the N-scored-runs capture loop (`_capture_case_run` currently accepts the first scored run; N≈5 collection runs live).
4. **P4 — Judge calibration (D):** gold-set + accuracy/bias/stability tests + seed + provenance. **SHIPPED (10df00b):** `bench/judge_gold.jsonl` (24 pairs, 13 MATCH/11 NO_MATCH, adversarial near-misses) + `bench/runner/judge_eval.py` (`GoldPair`, `evaluate_judge` → accuracy + confusion + leniency/strictness bias, `judge_stability`) + judge prompt now feeds GT `description` + key-gated real-judge accuracy/stability integration test (floor 0.80). **DEFERRED to P6 (needs live judge data):** per-run judge-decided-match-count provenance + the sole-arbiter-vs-keyword decision (informed by measured accuracy). **Seed:** Claude messages API has no documented seed param → stability is *measured* (not pinned).
5. **P5 — Threshold calibration (E):** σ-derived gate threshold + CITATION_THRESHOLD sweep + hallucination scoring. **OFFLINE CORE SHIPPED (4bba066):** `bench/grounding_labels.jsonl` (16 TP/FP pairs) + `bench/runner/threshold_calibration.py` (`citation_ratio`, `is_likely_hallucination`, `sweep_threshold`); **CITATION_THRESHOLD 0.4 → 0.325 (calibrated**, F1=1.0, separates hallucinated max 0.286 from genuine min 0.375), drift-guarded by a re-derivation test; `grounding.salient_tokens_from_text` shared with the live grounder. **DEFERRED:** the σ-derived CI-overlap gate threshold needs P6's real captured variance; the bench-pipeline `hallucination_rate` metric wiring lands with P6 (needs workspace files in the capture path).
6. **P6 — Capture the calibrated baseline (live, cost-gated):** run the full N×cases×modes capture; commit the CI baseline. *(Budget/time confirmed first.)*
7. **P7 — Audit-to-convergence + council** (same discipline as Track-2).

Each phase is independently testable; P1 (sidecar) and P2 (cases) are the foundation, P3 the statistical core, P4/P5 the calibration, P6 the live capture.

> **Sequencing note (P2 learning):** validate **case quality** (are GT findings genuine, distractors truly benign, `must_mention` discriminating) BEFORE the cost-gated P6 capture — P6 spends budget baselining against the GT, so a semantic GT error must be caught first (the deterministic `test_cases_validate` checks anchors/bounds/disjointness, not semantics). Fold a case-quality pass into the pre-P6 step or P7's audit. **The full deep review (code + security + Claude/ultrareview + council, audit-to-convergence) stays at P7 over the complete Track-3** (decided 2026-05-26).

## 9. Security

- Distractor + multi-finding case `workspace/` code is still **untrusted** — the existing tmpdir + `.git`-purge + path-containment + `disableAllHooks` isolation applies unchanged.
- The `*.findings.json` sidecar is parsed via `AdvisorFinding.model_validate_json` (`extra='forbid'`) — key-smuggling fails loud; `schema_version` gate.
- Gold-set + negative-anchor files are committed fixtures (trusted).
- No new secret surface; `claude --print` stays plan-billed.

---

## 10. Testing

- Sidecar: fixture-based extraction test (a captured real `*.findings.json`); schema-version mismatch test.
- Cases: every case's GT + negative anchors validate against the (extended) schemas; ≥1 mandatory + ≥1 optional per multi-finding case.
- Statistical: bootstrap-CI helper unit-tested with synthetic distributions; CI-overlap gate logic tested (overlap→pass, disjoint-drop→fail); harness-success-rate computed correctly.
- Judge: gold-set accuracy test (key-gated) + stability test + mocked unit tests.
- Threshold: the σ-derivation + sweep are reproducible scripts with recorded outputs.
- Gate: full suite green, `mypy --strict` + `ruff` clean throughout; no interactive-runtime behaviour change (sidecar is additive).

---

## 11. Success criteria

1. `/hydra` emits a valid `*.findings.json` sidecar; the bench consumes it (prose fallback intact); fixture-guarded.
2. Cases carry multi-finding GT (mandatory+optional) + distractors/negative anchors; recall/precision/F1/FP-rate all have dynamic range (no longer pinned).
3. The baseline is a capture-all median + bootstrap CI over N≈5 scored runs with a first-class harness success-rate; the gate **blocks** on non-overlapping CIs with a documented α, and distinguishes harness failure (exit 2) from regression (exit 1).
4. The judge has a committed gold-set with measured accuracy/bias + a stability test; judge-decided-match count is recorded per run.
5. The regression threshold + CITATION_THRESHOLD are calibrated from observed data (not heuristic), with recorded provenance; grounding-based hallucination scoring is wired.
6. Full suite green, `mypy --strict` + `ruff` clean; interactive review behaviour unchanged.
