---

## 0. Why this spec exists

ADR 0001 (Option C) settled the substrate question: **interactive `/hydra` stays in the
Claude-Code harness** (Agent tool + `codex-companion.mjs`), and the `hydra/` Python package
is **bench-scoped** — a *shared library of deterministic helpers* plus a *thin bench driver*.
Track 0 (ADR) and Track 1 (Grounding-Lite, suspicious-verdict gate, Echo, Mies+ — all shipped
as harness prompts) are merged (#8/#9/#10).

Track 2 builds the **only two things prompting genuinely cannot do**:

- **(A) Deterministic, non-LLM citation/grounding verification** — an LLM grounding *itself*
  is the problem being solved; a Python function that actually opens the cited file at the
  cited line range is strictly stronger than the prompt-based Grounding-Lite that ships today.
- **(B) Reproducible benchmark scoring** — measuring review quality across N runs requires a
  headless, scriptable, deterministic scorer. The harness Agent tool cannot do this; prompts
  cannot self-score reproducibly.

Everything else the original 44-task plan's "engine" bought (per-token Budget, prompt-cache
cost model, asyncio concurrency, direct-SDK advisor dispatch, OpenAI/Codex client) is **out of
scope** — it served the engine's own existence, not review quality. See §2/§3 Non-Goals.

## 1. Scope & Non-Goals

### 1.1 In scope (two pillars)

1. **Pillar A — Deterministic Citation/Grounding** (`hydra/grounding.py` + `python -m hydra ground` CLI).
2. **Pillar B — Reproducible Bench Scoring** (complete `bench/runner/*`: candidate extraction,
   hybrid matching engine, judge, orchestration, regression report, 1.x baseline).
3. **SDK modernization** narrowly where a direct LLM call is unavoidable (the bench judge):
   pin `anthropic`, add a contract test, use `messages.parse(output_format=...)`, add a
   `usage → TokenUsage` adapter.

### 1.2 Explicit Non-Goals (scope fences)

- **No runtime replacement.** SKILL.md + `references/*.md` remain the interactive product.
  Track 2 does not dispatch advisors, synthesize verdicts, or alter interactive behavior.
- **No direct-SDK advisor driver.** The bench invokes the *real shipped product* via
  `claude --print "/hydra this"` (decision D-2). No `AsyncAnthropic`, no OpenAI/Codex client,
  no re-implemented advisor dispatch. (ADR Option-A territory — rejected.)
- **No asyncio / TaskGroup / concurrency engine.** The deterministic core is pure synchronous
  Python. `seeder.py`, `concurrency.py`, `observability.py`, `injection_defense.py` are **not**
  built (decision D-3). `run_tool_async` stays deleted.
- **No prompt-cache cost model / Budget-as-release-gate.** The ≥60% cache-hit gate is moot:
  there is no direct-SDK advisor path to cache. `Budget`/`TokenUsage` remain only for accounting
  the (cheap) judge calls.
- **No git submodules in the MVP.** The 5 bench cases are self-contained (embedded `workspace/`
  + `diff.patch`). Submodule-pinned upstream repos (`bench/repos/`, `lockfile.json`,
  `PLACEHOLDER_UNTIL_TASK_35`) are a Part-6 full-bench concern, **deferred** (§8).
- **No SKILL.md grounding wiring in this spec.** The grounding CLI is built and tested here;
  having the interactive chairman *call* it via Bash is a separate follow-up increment
  (decision D-1, §8).

## 2. Pillar A — Deterministic Citation/Grounding Verification

### 2.1 Module & consumer surface

- **`hydra/grounding.py`** — pure functions, no LLM, no network, fully synchronous.
- **`python -m hydra ground`** CLI (via `hydra/__main__.py`) — reads a findings JSON file,
  runs grounding against a `--repo` root, prints the Grounding Summary, writes grounded findings.
- **Primary consumer:** the bench (Pillar B), to measure Hydra's grounding accuracy.
- **Deferred consumer:** the interactive chairman (SKILL.md wiring) — out of scope here (§8).

### 2.2 Input contract — reconcile spec §5.1 drift

The authoritative grounding pseudocode lives in `docs/specs/2026-04-17-hydra-2.0-core-design-v2.md`
§5.1, but it references `finding.chain.code_construct` — a field that **does not exist**. The
shipped `Chain` (`hydra/envelopes.py:71-80`) is the 3-field model `premise / execution_trace /
conclusion`. Likewise `evidence` (`envelopes.py:103`) is a closed `Literal` enum
(`VERIFIED | HYPOTHESIS_HIGH | HYPOTHESIS_MEDIUM | HYPOTHESIS_LOW`), **not** free-text code.

**Decision (RECONCILE-1):** grounding operates on the real `AdvisorFinding`
(`envelopes.py:93-116`). Salient tokens for citation matching are extracted from the
**free-text code-claim fields**: `title` + `chain.premise` + `chain.conclusion`
(`chain.execution_trace` optional — it narrates rather than names constructs). `evidence` and
`severity`/`position` are used for the safety/applicability gates, not token extraction.
Spec §5.1 must be patched (or annotated) to remove the `code_construct` reference; this spec is
authoritative for Track-2 implementation.

### 2.3 `ground_finding` algorithm

Synchronous; mirrors spec §5.1 with the reconciled token source and the verified
`contained_path` API (`hydra/path_safety.py:14-60`).

```
SAFETY_POSITIONS = {APPROVE}        # grounding cannot verify a safety claim (P-5)
SAFETY_SEVERITIES = {TRIVIAL}

def ground_finding(finding: AdvisorFinding, repo_root: Path) -> AdvisorFinding:
    if finding.position in SAFETY_POSITIONS or finding.severity in SAFETY_SEVERITIES:
        finding.grounding = NOT_APPLICABLE; return finding

    if not finding.file or not finding.lines:
        finding.grounding = NO_CITATION; demote(finding); return finding

    try:
        # must_exist=False: run the relative_to() escape check BEFORE existence so
        # PATH_ESCAPE takes precedence over FILE_MISSING (escaping citation = red flag).
        resolved = contained_path(repo_root, finding.file, must_exist=False)
    except PathEscapeError:                 # out-of-repo citation = red flag (S-2)
        finding.grounding = PATH_ESCAPE; return finding   # caller drops to degradation panel
    if not resolved.exists():
        finding.grounding = FILE_MISSING; demote(finding); return finding

    range_text = read_range(resolved, finding.lines)   # parse "142-158" | "142"
    if range_text is None:                  # range out of bounds / unparseable
        finding.grounding = RANGE_MISSING; demote(finding); return finding

    tokens = extract_salient_tokens(finding)           # §2.2 reconciled source
    ratio = count_present(tokens, range_text) / max(len(tokens), 1)
    finding.grounding = CITATION_PRESENT if ratio >= CITATION_THRESHOLD else TOKEN_MISMATCH
    if finding.grounding == TOKEN_MISMATCH: demote(finding)
    return finding
```

- **`GroundingStatus`** values already exist (`envelopes.py:25-33`): `UNKNOWN, CITATION_PRESENT,
  NOT_APPLICABLE, NO_CITATION, FILE_MISSING, RANGE_MISSING, TOKEN_MISMATCH, PATH_ESCAPE`. No enum
  change needed.
- **`PATH_ESCAPE`** vs **`FILE_MISSING`** (escape-first, verified during impl): call
  `contained_path(must_exist=False)` so the `relative_to(root)` escape check
  (`path_safety.py:48`) fires *before* any existence check; a `PathEscapeError` → `PATH_ESCAPE`.
  Then an explicit `resolved.exists()` → `FILE_MISSING`. Using `must_exist=True` would let
  `FileNotFoundError` mask a genuine escape for paths that both escape and are absent.
- **`read_range(path, lines)`**: parse `lines` (string `"N"` or `"N-M"`, same grammar as
  `bench/runner/scoring.py:25-30`), 1-indexed inclusive; return the joined source lines, or
  `None` if the range falls outside the file. Caps BOTH lines and bytes read
  (`max_lines * max_line_bytes` ceiling) so a pathological single-line file can't be slurped (§6).
- **`extract_salient_tokens(finding)`**: identifiers / quoted literals / call names from
  `title + chain.premise + chain.conclusion`; split on whitespace+punctuation, drop stopwords,
  keep tokens ≥3 chars, cap at 8 (per spec §5.1).
- **`CITATION_THRESHOLD = 0.4`** — starting point; **calibrated on the 5 bench cases** during
  implementation (spec §5.1 Echo E-1; calibration is a plan task, not a guess).

### 2.4 Severity-demotion ladder

`CATASTROPHIC > SERIOUS > MODERATE > MINOR > TRIVIAL` (`Severity`, `envelopes.py:11-16`).
`demote()` drops exactly one rung; `CATASTROPHIC → SERIOUS`; `TRIVIAL` is the floor (no further
demotion).

**Divergence note (intentional):** the shipped *prompt* Grounding-Lite uses a `MODERATE` floor
because its prompt vocabulary is coarser (no MINOR/TRIVIAL). The Python enum has all five rungs,
so the deterministic check uses the **full ladder with a `TRIVIAL` floor** per spec §5.1. The
two are different implementations of the same intent at different fidelity; this is documented,
not a bug.

### 2.5 Grounding Summary output

Emitted by the CLI and returned by a `summarize(findings)` helper (spec §5.1 format):

```
## Grounding Summary
- Findings total: 17
- CITATION_PRESENT: 12 (70.6%)
- NOT_APPLICABLE (safety claim): 3
- Auto-demoted: 2 (1 TOKEN_MISMATCH, 1 FILE_MISSING)
- Dropped (PATH_ESCAPE): 0
```

## 3. Pillar B — Reproducible Bench Scoring

### 3.1 Ground-truth schema — reconcile drift

Current `expected_findings.jsonl` (the 5 cases) carries `{file, lines(str), severity,
issue_class, mandatory, ...}`. Spec §11.3 specified `{file, line_start, line_end, must_mention,
severity, cwe}`. The current `scoring.py` reads `lines`/`issue_class`/`mandatory`;
`bench/runner/extract_findings.py:29` hardcodes `issue_class="other"` for every 1.x candidate,
so the `issue_class` match bonus (`scoring.py:50`) **never fires for 1.x baselines** — a real,
silent scoring gap.

**Decision (RECONCILE-2): additive migration, do not churn the 5 cases' line format.**
- Keep `lines` as a string range (works today, one parser).
- **Add `must_mention: list[str]`** (keyword alternatives, ≥1 must match — enables the hybrid
  judge, §3.3) and **`cwe: str | None`** (security traceability) to each ground-truth line.
- Keep `mandatory: bool` (drives `critical_recall`).
- Define a `GroundTruthFinding` pydantic model so the schema is validated, not duck-typed.

### 3.2 Candidate extraction

- **1.x reports** (`extract_findings.py`): parse YAML frontmatter `top_actions[]` (current
  behavior). **Fix the `issue_class="other"` dead bonus** — either drop the `issue_class`
  weight for 1.x candidates (honest: 1.x carries no class) or map from the report's category
  if present. Decision: drop the `issue_class` bonus when a candidate's class is the default
  `other`, so matching rests on file+range+keywords (no phantom 0.5 that can never fire and
  no false negatives from comparing `other` to a real class).
- **2.0 structured findings:** add an extractor that loads `list[AdvisorFinding]` JSON (the same
  shape the grounding CLI emits), so the bench can score the structured pipeline once it exists.

### 3.3 Matching engine — hybrid (deterministic-primary + judge fallback)

**Decision (D-Scoring): hybrid.** Reproducible by default, semantic safety net at minimal cost.

1. **Deterministic pre-filter** (existing `scoring._match_score`, `scoring.py:42-54`):
   `file` exact match **and** range overlap. **Calibrate tolerance to ±5** per spec §11.4
   (currently hardcoded `tol=10`, `scoring.py:33`) — make it a named, configurable constant and
   default to 5; validate the choice against the baseline before freezing.
2. **Deterministic keyword match:** a candidate matches its ground-truth finding if ≥1
   `must_mention` keyword is present in the candidate's text. **Fully deterministic, $0.**
3. **Judge fallback (LLM, narrow):** *only* for candidates that **pass the file+range
   pre-filter but fail the keyword match** — the ambiguous middle. A single judge call
   (`messages.parse(output_format=JudgeVerdict)`, §4.2) decides `MATCH | NO_MATCH`. The judge is
   blind to Hydra version, sees only `{gt description, must_mention, candidate}` (spec §11.4
   mitigations), `temperature=0`. Most runs invoke the judge zero times → near-deterministic,
   near-$0.
- `JUDGE_ENABLED` env flag (default on) so a fully-deterministic CI run (no API key) degrades
  gracefully to keyword-only matching with a logged warning.

### 3.4 Metrics

Keep the verified `CaseScore` (`scoring.py:7-15`): `recall, precision, f1, critical_recall,
matched, missed, noise`. Greedy one-to-one matching (`scoring.py:57-78`) stays. Aggregate across
runs = **median** (already in `run_bench.write_baseline`, `run_bench.py:52-61`).

### 3.5 Invocation substrate

**Decision (D-2): keep `claude --print "/hydra this"`** (`invoke_hydra_1x.py:95-102`). It is the
already-built, plan-billed (≈$0 marginal), headless path that exercises the **real shipped
product** including deep-mode Codex advisors. The `.git`-purge RCE fix
(`invoke_hydra_1x.py:59-68`) and case-id containment (`:26-42`) stay.
- **Accepted limitation:** no per-advisor `temperature`/`seed`/cache-hit telemetry (that needs
  the rejected direct-SDK path). Reproducibility rests on pinned model IDs, fixed prompts,
  median-of-N runs, and a frozen baseline — not on advisor-level seeds.

### 3.6 Orchestration, baseline, regression

- **`bench/runner/run_bench.py`** grows from single-case utility into an orchestrator:
  - **fast-bench** (spec §11.5): cases #1 + #4, 1 run, standard mode — the per-commit gate.
  - **full-bench** (spec §11.6): all 5 cases, 3 runs, standard×1 + deep×1 — the release gate.
  - Case discovery from `bench/cases/`; per-case invoke → extract → score → median.
- **1.x baseline capture** (spec §11.9): `invoke_hydra_1x.py` already writes the baseline JSON
  (`run_bench.write_baseline`, `run_bench.py:40-70`). Capture once against `main@3506f93` and
  commit `bench/baselines/hydra-1.x-<date>.json` as the immutable regression reference. Cost is
  CLI plan time (≈$4-7-equiv), not API spend.
- **`bench/runner/report.py`** (new): the regression rule (spec §11.7) — **fail if median F1
  drops ≥10 pp on ≥2 of 5 cases** vs baseline; fast-bench single-case >15 pp drop → soft-warn.
  Exit non-zero on red so it gates CI.

## 4. SDK modernization (narrow — judge path only)

### 4.1 Pin `anthropic` + contract test

- Installed: `anthropic 0.96.0`; pyproject pins only the floor `>=0.45.0`
  (`pyproject.toml`, `[llm]` extra). **Pin to a tested range** (e.g. `>=0.96,<0.97`) in a
  `[judge]` (or reused `[llm]`) extra, moved into real deps in the commit that adds the first
  `import anthropic`.
- **Contract test** (`tests/integration/`, skippable without API key): assert
  `Anthropic().messages.parse` exists and that a parsed response exposes the `usage` fields the
  adapter depends on (§4.3). This is the regression guard against the 0.45→0.96 drift recurring.

### 4.2 `messages.parse(output_format=...)` for the judge

Replace the dated `emit_findings` tool-coercion pattern (never built; was Task 18) with native
structured output: a `JudgeVerdict` pydantic model (`{verdict: Literal["MATCH","NO_MATCH"],
reason: str}`) passed as `output_format`. Deterministic shape, no tool-call plumbing.

### 4.3 `usage → TokenUsage` adapter

`Budget`/`TokenUsage` (`hydra/budget.py:8-14`) use `input/output/cache_read/cache_write_5m/
cache_write_1h`; the SDK exposes `input_tokens/output_tokens/cache_read_input_tokens/
cache_creation_input_tokens`. Add `usage_to_tokens(response.usage) -> TokenUsage`:
`input←input_tokens`, `output←output_tokens`, `cache_read←cache_read_input_tokens`,
`cache_write_5m/1h←0` for the judge (no caching on judge calls; the 5m/1h split needs the
`extended-cache-ttl` beta and is irrelevant here). Budget tracks judge spend only — trivial.

## 6. Security

- **Untrusted bench code reaches an LLM** only via the existing `claude --print` path (the real
  product's own injection defenses apply) and via the **judge**, which sees only
  gt-description + must_mention + a single candidate finding — never raw repo code. Keep it that way.
- **Path containment:** all file access in grounding goes through `contained_path`
  (`path_safety.py`) — absolute-path reject, PATH_MAX, symlink canonicalization, case-fold
  tripwire. `read_range` must not read outside the `contained_path` result.
- **`.git` purge before `git init`** in the bench workspace stays (`invoke_hydra_1x.py:59-68`) —
  the live-RCE regression guard.
- **`read_range` DoS cap:** bound bytes/lines read so a malicious `lines: "1-99999999"` cannot
  exhaust memory.
- **Judge prompt injection:** the candidate finding text is untrusted; the judge prompt must
  fence it and constrain output to the `JudgeVerdict` schema (structured output limits blast radius).

## 7. Testing strategy

- **Deterministic core = exhaustive unit tests** (no LLM, no network): `ground_finding` across
  every `GroundingStatus` branch; `read_range` parsing + out-of-bounds + DoS cap; path-escape /
  file-missing distinction; `extract_salient_tokens`; demotion ladder incl. CATASTROPHIC→SERIOUS
  and TRIVIAL floor; the hybrid matcher with keyword hit/miss; `GroundTruthFinding` schema validation.
- **Judge = mocked** for unit tests (assert it's invoked *only* on the file+range-pass /
  keyword-fail subset); **one skippable live contract test** (§4.1) behind an API-key guard,
  mirroring the existing `CODEX_SKIP_LIVE` pattern (`tests/integration/test_codex_live.py`).
- **Regression report:** unit-test the ≥10pp/≥2-of-5 rule with synthetic baselines (red/green/warn).
- Gate: full suite stays green (**159 passed / 5 skipped** at Track-2 completion); `mypy --strict` + `ruff` clean.

## 9. Success criteria

1. `hydra/grounding.py` + `python -m hydra ground` produce a correct Grounding Summary on a
   findings JSON, with every `GroundingStatus` branch unit-covered.
2. `bench/runner` runs **fast-bench** (cases #1+#4) and **full-bench** (5×3) end-to-end against
   the embedded workspaces via `claude --print`, producing per-case + median F1/P/R/critical-recall.
3. A committed **1.x baseline** exists; `report.py` correctly flags a synthetic ≥10pp/≥2-of-5
   regression (exit non-zero) and passes a no-regression run.
4. The hybrid matcher invokes the judge **only** on the file+range-pass / keyword-fail subset and
   degrades to keyword-only without an API key.
5. `anthropic` is pinned with a passing contract test; the judge uses `messages.parse`; the
   `usage → TokenUsage` adapter is unit-tested.
6. Full test suite green, `mypy --strict` + `ruff` clean. No interactive-runtime behavior changed.

## Late discoveries & amendments (2026-05-26, during implementation + audit)

Surfaced by the live 1.x baseline capture and the final multi-agent audit; all fixed:

- **Real report format ≠ assumed (§3.2 amended).** Live reports lead with a
  `<!-- hydra-integrity: ... -->` comment (broke the old `startswith("---")` frontmatter
  check) and carry findings in the `## Actions` body as `### A{N} <sep> SEV <sep> file:lines
  <sep> Est:` headings. `extract_from_report` is now **body-primary** (bug-descriptive What/Why
  text, better for `must_mention`) with a **frontmatter fallback** + comment strip. The heading
  `<sep>` is ASCII `--` OR em/en-dash (`—`/`–`) — the parser accepts all. Candidate/GT line specs
  may be comma multi-spans (`"15,21-22"`); both `scoring._parse_ranges` and `grounding._parse_line_range`
  handle them (overlap if ANY sub-span matches).
- **Headless invocation interference + reliability (§3.5 amended).** A user-level Stop hook
  returning `{"decision":"block"}` hijacks the headless `claude --print` session; fixed by passing
  `--settings '{"disableAllHooks": true}'` in `invoke_hydra` (hooks disabled for the bench
  subprocess only; CLAUDE.md/skills/plugins still load — unlike `--bare`). Even hooks-off, the
  nested multi-agent `/hydra` is ~40–50% unreliable headless (timeout / no-report / action-less
  variance). **§11.9 baseline methodology amended:** the committed 1.x baseline is a *single
  retried good run per case* (retry transient/degraded runs until recall>0), NOT median-of-3 — a
  reproducible median-of-3 release baseline would need ~30 reliable runs and is deferred.
- **Regression gate wired (§3.6).** `report.check_regression` is now invoked via
  `python -m bench.runner.run_bench bench --mode <m> --check-baseline <path>` (exit 1 on release
  regression). Soft-warn (>15pp single-case → non-failing yellow) implemented per §11.7.
  **ADVISORY against the current single-run baseline:** the §11.7 ≥10pp/≥2-of-5 rule assumes
  median-of-N runs + multi-finding ground truth; against a single retried run with one mandatory
  finding/case it is variance-prone and blind to single-case loss, so `gate_against_baseline`
  prints an `[ADVISORY]` banner and it must NOT be wired into a *blocking* CI step until the
  median-of-N baseline + multi-finding cases land.
- **§4.3 usage→TokenUsage adapter descoped.** The judge is bench-only and cheap; no Budget
  enforcement consumes it, so the adapter was removed (YAGNI). The contract test guards the
  surface the judge actually uses (`messages.parse` + `output_format` + `temperature` + `parsed_output`).
- **RECONCILE-1 patch applied** to the prior design `docs/specs/2026-04-17-...-v2.md` §5.1.
